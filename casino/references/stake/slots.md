## 1. Random number generation (Stake, "Implementation" page)

For each verifiable bet, a **client seed**, a **server seed**, a **nonce** and a **cursor** are the inputs to the random number generation function, which uses **HMAC_SHA256**. Stake's published generator code:

```js
// Random number generation based on following inputs: serverSeed, clientSeed, nonce and cursor
function byteGenerator({ serverSeed, clientSeed, nonce, cursor }) {
  // Setup curser variables
  let currentRound = Math.floor(cursor / 32);
  let currentRoundCursor = cursor;
  currentRoundCursor -= currentRound * 32;

  // Generate outputs until cursor requirement fullfilled
  while (true) {
    // HMAC function used to output provided inputs into bytes
    const hmac = createHmac('sha256', serverSeed);
    hmac.update(`${clientSeed}:${nonce}:${currentRound}`);
    const buffer = hmac.digest();

    // Update curser for next iteration of loop
    while (currentRoundCursor < 32) {
      yield Number(buffer[currentRoundCursor]);
      currentRoundCursor += 1;
    }
    currentRoundCursor = 0;
    currentRound += 1;
  }
}
```

Published notes on the inputs:

- **Server seed** — "generated by our system as a random 64-character hex string. You are then provided with an encrypted hash of that generated server seed before you place any bets." To reveal it, the seed must be rotated by the player.
- **Client seed** — belongs to the player; "created for you by your browser" at registration and freely changeable ("similar to cutting the deck at a brick and mortar casino").
- **Nonce** — "simply a number that increments as every new bet is made."
- **Cursor** — "We use 4 bytes of data to generate a single game result, and because SHA256 is limited to 32 bytes, we utilise this implementation of a cursor... The cursor starts as 0 and gets increased by 1 every time the 32 bytes are returned by the HMAC_SHA256 function."
- Stake's published per-game cursor list states, under "Games with more than 1 incremental number": **"Slots (The incremental number is only utilised for bonus rounds)"** — i.e. a base spin fits within one 32-byte HMAC round (≤ 8 floats); the cursor increments only when a bonus round requires more game events.

## 2. Bytes → floats (Stake, "Conversions" page)

> "The output of the Random Number Generator (byteGenerator) function is a hexadecimal 32-byte hash... we use 4 bytes of data to generate a single game result. Each set of 4 bytes are used to generate floats between 0 and 1 (4 bytes are used instead of one to ensure a higher level of precision when generating the float.)"

```js
// Convert the hash output from the rng byteGenerator to floats
function generateFloats ({ serverSeed, clientSeed, nonce, cursor, count }) {
  // Random number generator function
  const rng = byteGenerator({ serverSeed, clientSeed, nonce, cursor });
  // Declare bytes as empty array
  const bytes = [];

  // Populate bytes array with sets of 4 from RNG output
  while (bytes.length < count * 4) {
    bytes.push(rng.next().value);
  }

  // Return bytes as floats using lodash reduce function
  return _.chunk(bytes, 4).map(bytesChunk =>
    bytesChunk.reduce((result, value, i) => {
      const divider = 256 ** (i + 1);
      const partialResult = value / divider;
      return result + partialResult;
    }, 0)
  );
};
```

Equivalently, each float = `b0/256 + b1/256^2 + b2/256^3 + b3/256^4`, giving a uniform value in [0, 1).

## 3. Floats → slot game events (Stake, "Game Events" page)

### 3a. Scarab Spin / Tome of Life (fixed reels)

Stake's published game-event translation, verbatim:

> "The game event number is calculated by multiplying the float by the possible outcomes in the reel. The first 4 reels have a length of 30 possible outcomes, whilst the last reel has 41. The game event determines the central stop position for each reel. This game consists of 5 game event numbers, until the case of a bonus round, where more are generated."

In other words, for each base spin, 5 floats are generated (one per reel) and:

- Reels 1–4: `stop = floor(float * 30)` (30 possible central stop positions each)
- Reel 5: `stop = floor(float * 41)` (41 possible central stop positions)

The stop is the **central** position of the visible 3-symbol window on each reel of the 5×3 grid. Bonus rounds generate additional game events (this is where the cursor increments — see §1).

### 3b. Blue Samurai (dynamic weighted reels)

Stake's published game-event translation, verbatim:

> "Blue Samurai slots has 3 different types of spins. Regular, bonus and special.
>
> For regular and bonus spins, 18 floats from 0 to 1 are generated from your hash. Unlike Scarab Spin slots, which has fixed reels, Samurai slots has dynamic reels, meaning each symbol is generated from the corresponding float that was assigned to it.
>
> We use weighted random sampling to assign each float to its corresponding tile, in the same order, moving down the reels, from left to right. Each symbol has its own fixed probability / chance of appearing in any one tile, with the outer 2 reels having a different set of probabilities to the inner 3 reels. For a bit more information on how symbols are selected, see fitness proportionate selection algorithm to learn more.
>
> Special spins are slightly different. For a start only 12 floats are taken from your hash, as the outer reels are disabled. Between each special spin, any samurai symbols stay in place for the remainder of the game, with the result being the final count of samurais. This means that if you were to have for example 1 samurai stick in the first spin - we'd technically only need 11 floats for the subsequent spin. For the sake of simplicity in the probably fair model, we just generate 12 floats every time, and if the float that was allocated for a tile has a stuck samurai from a previous spin, then that float is not used at all."

(Note: 18 floats — Stake's page states 18; the visible grid is 5 reels; the outer 2 reels use a different symbol-probability set than the inner 3. Symbol selection is fitness-proportionate/weighted sampling per tile, ordered down each reel, reels left to right. Special spins use 12 floats because the outer reels are disabled.)

All Stake Originals slots outcomes are verifiable in Stake's own fairness calculator (games listed there include "Scarab Spin", "Blue Samurai", "Tome of Life"): https://stake.com/provably-fair/calculation

- Published **house edge 2.16%** ("Edge: 2.16 %" badge) / **RTP 97.84%**: "Tome of Life has one of the highest return to player percentages at 97.84% and a house edge of 2.16%."

## 6. Blue Samurai — rules, paytable, house edge (Stake game pages)

- 5 reels, **40 fixed paylines**; "all wins are multiplied by the bet per line, not the total bet"; "You can earn a payout by **matching 4-5 of a kind** on a payline."
- Published **house edge 3.30%** ("Edge: 3.30 %" badge on stake.com game page) / **RTP 96.70%**: "a **96.70% theoretical return-to-player percentage** (RTP)... The low house edge of 3.30%" (stake.com game page and stake.com blog guide; the stake.com page calls it high volatility). The stake.us page text states "a theoretical return to player percentage of **97.26%**, with a medium-volatility level" — Stake has published both figures; the stake.com Edge badge and blog agree on 96.70% / 3.30%.
- 10 standard symbols, 1 wild, 1 scatter. Wild: "substitutes for all regular paying symbols... When multiple wilds form wins, only the highest multiplier will be applied."
- Free spins: "Scatter symbols... can drop on **reels 2, 3, and 4** [only]. If you land three scatters in view, you will trigger the bonus round with **10 free spins**, which can be retriggered up to a cap of **180 bonus spins**."
- Samurai Bonus (special game): "you can access if the **first or fifth reel is spun with three samurai**. During this special game, you have **5 chances to fill the board exclusively with Samurai**... The special game pays out according to its unique paytable, which you can find in the game info for this slot. Click the 'Bonus Round' box to view the special paytable option." (The special-game paytable — payout by final samurai count — is published only inside the game client's Game Info panel; Stake's static pages state it exists but do not list its values.)

## 7. Verbatim gaps / caveats

- The per-reel **reel strips** (the symbol order across the 30/30/30/30/41 stop positions of Scarab Spin / Tome of Life) and Blue Samurai's per-tile **symbol weights** are implemented inside Stake's fairness-calculation client (stake.com/provably-fair/calculation) and the game clients, but are not printed as human-readable tables on any static Stake page; Stake publishes the stop-selection / weighted-sampling math (§3) and directs players to the in-game "Game Info → Pay Table" tab for line payouts (fully captured in §4–§6 from Stake's game pages).
- Blue Samurai's special "Samurai Bonus" paytable is likewise published only in the in-game Game Info ("Bonus Round" box), per Stake's own game page.
- Stake has published two RTP figures for Blue Samurai (96.70% on stake.com; 97.26% in older stake.us page text) — both captured above.
